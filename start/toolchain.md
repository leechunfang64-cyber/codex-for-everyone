# 我的工具链

工具链不是越多越好。真正重要的是每个工具在生产链条里承担什么角色。

## 核心工具

| 工具 | 角色 |
| --- | --- |
| ChatGPT | 想法拆解、文章结构、提示词草稿、跨领域判断 |
| Codex | 进入本地项目，读文件、改代码、跑验证、排障 |
| Claude Code | 长上下文代码理解、另一套实现视角和复核 |
| Gemini | 多模型交叉验证、资料理解、低成本探索 |
| GitHub | 版本管理、开源展示、协作入口 |
| Vercel | 快速部署 Web 应用和原型 |
| Cloudflare Pages | 静态站点、文档站、自定义域名 |

## 分工原则

ChatGPT 适合想清楚，Codex 适合做出来，GitHub 适合沉淀，部署平台适合让外部用户访问。

不要把所有工作都塞给一个工具。真正高杠杆的流程是：

1. ChatGPT 帮你把需求和文章结构想清楚。
2. Codex 在本地把代码和文档落地。
3. GitHub 保留过程和资产。
4. Cloudflare Pages 或 Vercel 把结果上线。
5. 再把案例拆成内容、教程、模板和产品入口。

## 不要做工具收藏癖

收藏工具不会产生现金流。能产生价值的是：

- 一个上线的工具。
- 一个能复用的模板。
- 一篇能带来信任的教程。
- 一个能降低交付成本的流程。

工具只是生产资料的一部分，不是生产结果本身。
