# Codex 是什么

Codex 是 OpenAI 面向编程工作的 AI agent。它可以读文件、理解代码库、修改代码、运行命令、解释错误，并在一次次反馈里推进项目。

更准确地说，Codex 不是“替你写代码的按钮”，而是一个能进入工程现场的协作者。它的价值不在一口气生成多少代码，而在能否围绕一个具体目标持续读上下文、改文件、跑验证、修错误。

## 它适合做什么

- 读一个陌生项目，解释结构和关键模块。
- 根据需求实现一个小功能。
- 修复构建、测试、类型、部署错误。
- 把重复开发动作整理成脚本、模板和文档。
- 把一次真实开发复盘成教程或案例。

## 它不适合做什么

- 替你判断一个需求是否值得做。
- 在没有上下文时猜出正确业务规则。
- 保证第一次生成就完全正确。
- 替你承担安全、成本、交付和售后责任。

## 正确预期

Codex 能提高执行速度，但不能替代需求判断。需求错了，代码越快越危险。商业上最贵的不是写代码，而是做错东西后还继续投入。

所以使用 Codex 的第一原则是：先让需求变清楚，再让代码变快。

## 最小工作流

1. 说明目标和边界。
2. 让 Codex 先读现有文件。
3. 要求它给出实现计划。
4. 分阶段改代码。
5. 运行验证命令。
6. 把问题反馈回去继续修。
7. 记录提示词、命令和坑点。

这套流程看似慢，实际是在降低返工成本。真实项目里，最容易吞掉利润的不是开发，而是反复返工、线上故障和无法复用。
