# 第一个项目怎么开始

第一个 Codex 项目不要选大而全的产品。选一个你自己马上会用、输入输出明确、一天内能验收的小工具。

## 推荐项目标准

- 你自己有真实需求。
- 输入和输出能写清楚。
- 不依赖复杂账号体系。
- 不需要支付、权限、多人协作。
- 失败成本低。

## 推荐从命令行工具开始

命令行工具不性感，但适合新手练基本功。原因很现实：

- 少掉界面复杂度。
- 更容易写测试。
- 错误更容易复现。
- 能更快判断需求是否成立。

比如先做一个 Markdown 转 Word 工具。跑通后再考虑界面、拖拽上传、批量处理和付费版本。

## 第一个提示词

```text
我想做一个最小可用工具，用来解决下面的问题：

目标：
输入：
输出：
必须支持：
暂时不支持：
验收方式：

请先帮我拆解需求，判断最小版本应该怎么做。不要急着写代码。
```

## 第一个项目的完成标准

完成不是“Codex 回复了代码”，而是：

- 代码在本地跑通。
- README 写清楚安装和使用。
- 常见报错有处理方式。
- 你能把过程复述给别人。
- 你知道下一次怎么复用这个模式。

这才是从工具使用者走向建设者的第一步。
