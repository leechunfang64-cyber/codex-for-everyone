# 开发小红书产品素材库

## 适用场景

小红书产品素材库适合内容团队或一人公司整理封面、标题、卖点、案例图、产品截图、发布记录和复盘数据。它的本质不是素材存储，而是内容生产系统。

## 需求拆解

- 输入：图片、标题、正文、标签、产品、发布时间、效果数据。
- 输出：可搜索、可筛选、可复用的素材库。
- 核心维度：产品、场景、风格、转化目标、发布时间、数据表现。
- 验收：能快速找到可复用素材，而不是只把文件堆起来。

## Codex 提示词

```text
我要开发一个小红书产品素材库 MVP。
目标用户是一人公司运营者。
第一版用本地 JSON 或 SQLite 存储，支持上传图片信息、记录标题正文、按产品和标签筛选。
请先设计数据结构、页面结构和最小可用功能，不要做复杂后台。
```

## 实现步骤

1. 定义素材数据模型。
2. 做列表、详情、筛选和新增表单。
3. 图片先用本地路径或对象存储 URL。
4. 增加标签和产品维度。
5. 后续再加数据复盘字段。

## 验证方式

- 新增一条素材。
- 按产品筛选。
- 按标签筛选。
- 打开详情页查看标题、图片、正文和复盘字段。

## 常见坑

- 只做图片墙，不做复盘字段。
- 标签体系过细，导致维护成本过高。
- 一开始做复杂权限，拖慢 MVP。

## 可复用资产

- 内容素材数据模型。
- 标签筛选界面。
- 内容复盘模板。
- 小红书选题和封面复用流程。

## 产品化判断

素材库的价值在于降低内容生产成本。如果它只是“存图片”，价值很低。如果它能帮助你复用卖点、识别爆款结构、减少重复思考，就是一人公司的生产资料。
