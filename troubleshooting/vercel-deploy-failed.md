# Vercel 部署失败怎么办

## 现象

Vercel 部署失败，常见表现包括 build error、环境变量缺失、Node 版本不一致、输出目录错误、API 路由超时或免费额度异常消耗。

## 判断路径

先区分失败发生在哪一层：

- 本地 build 失败。
- Vercel build 失败。
- 部署成功但页面运行失败。
- 页面能打开但后台请求失败。
- 流量或函数调用异常。

## 命令

本地先跑：

```bash
npm install
npm run build
```

检查环境变量：

```bash
vercel env ls
```

查看部署日志：

```bash
vercel logs <deployment-url>
```

## 预期输出

本地 build 必须先通过。否则上 Vercel 只是把错误搬到云端，排障成本更高。

## 错误分叉

- 本地成功，Vercel 失败：检查 Node 版本、环境变量、构建命令和输出目录。
- 部署成功，页面 500：检查服务端日志和环境变量。
- 页面正常，API 异常：检查路由、鉴权、数据库连接。
- 用量异常：检查是否有隐藏轮询、后台任务或动态路由被频繁触发。

## 不要做什么

- 不要只看 “Deployment Completed” 就认为产品健康。
- 不要把密钥写死在代码里。
- 不要忽略免费额度和函数调用成本。
- 不要在没有日志的情况下猜原因。

部署不是终点。真正的商业系统要看稳定性、成本和可回滚。
