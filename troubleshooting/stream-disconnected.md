# stream disconnected 怎么处理

## 现象

Codex 执行过程中出现 `stream disconnected`，或者生成、读文件、跑命令到一半断开。

## 判断路径

先判断这是一次瞬时中断，还是稳定复现：

- 只出现一次：可能是网络抖动或服务端临时中断。
- 每次长任务都出现：可能是网络代理、WebSocket、超时或上下文过大。
- 只在某个仓库出现：可能是命令卡住、输出过大、文件过多。

## 命令

检查当前网络和诊断：

```bash
codex doctor --summary
```

检查仓库是否异常庞大：

```bash
find . -type f | wc -l
du -sh .
```

检查是否有大文件：

```bash
find . -type f -size +20M -print
```

## 预期输出

如果仓库里有大量构建产物、日志、图片或依赖目录，应该用 `.gitignore` 和任务边界减少 Codex 需要读取的内容。

## 错误分叉

- 长输出命令导致断流：让 Codex 限制输出，或把任务拆小。
- WebSocket 不稳定：回到 reconnecting 的网络排障路径。
- 仓库过大：先清理构建产物和无关文件。

## 不要做什么

- 不要让 Codex 一次性分析整个大目录。
- 不要把日志无限制粘贴进上下文。
- 不要在网络未稳定时执行长时间自动任务。

长任务要拆。AI agent 的稳定性，也要靠工程边界来保护。
