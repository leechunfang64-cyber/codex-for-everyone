# API Key 泄露怎么补救

## 现象

API Key 被提交到 GitHub、发到群聊、贴进截图、写进前端代码，或者怀疑已经被他人使用。

## 判断路径

密钥泄露后，第一目标不是解释原因，而是止损：

1. 立即撤销泄露的 Key。
2. 创建新 Key。
3. 更新部署平台和本地环境变量。
4. 检查账单和调用日志。
5. 清理 Git 历史和公开材料。

## 命令

查找仓库中的疑似密钥：

```bash
rg -n "sk-|api[_-]?key|token|secret|password" .
```

检查 Git 历史是否出现过：

```bash
git log -p --all -S "sk-"
```

检查当前 `.env` 是否被跟踪：

```bash
git ls-files | rg "^\\.env"
```

## 预期输出

撤销旧 Key 后，即使别人拿到了旧值，也不能继续调用。新 Key 只配置在需要的环境里。

## 错误分叉

- 只删除当前文件不够：Git 历史里可能还在。
- 只改本地不够：部署平台可能仍使用旧 Key。
- 只换 Key 不查账单：可能已经产生异常调用。

## 不要做什么

- 不要在公开 issue 里贴完整 Key。
- 不要截图展示环境变量页面。
- 不要以为删除 GitHub 文件就彻底安全。
- 不要继续使用泄露过的 Key。

密钥泄露是现金流风险，不是面子问题。止损速度比解释更重要。
